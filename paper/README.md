# TreeStack paper

`main.tex`, `sections/*.tex`, and `references.bib` are the canonical article source.
`TreeStack.pdf` is the compiled inspection copy. The arXiv source archive is
`arxiv/TreeStack-arxiv.tar.gz`; it is generated from the same source, with the
compiled `main.bbl`. There is no separate arXiv edition.

The public preprint is [arXiv:2609.31811](https://arxiv.org/abs/2609.31811)
in math.CO. Version 1 was submitted on 2026-09-25 and carries the same Palomar
verification record as the repository article.

`proof-correspondence.md` records the adversarial mapping from the paper's
central statements to the checked Lean declarations. `upper-proof-map.md`
gives the more detailed correspondence for the weighted upper-bound section.

## Build and preflight

Install Python 3, a standard TeX Live distribution with pdfLaTeX and BibTeX,
and Poppler (`pdfinfo` and `pdftotext`). The article uses standard TeX Live
packages. On Debian/Ubuntu the packages used by CI are:

```sh
sudo apt-get install texlive-latex-base texlive-latex-recommended texlive-latex-extra texlive-fonts-recommended lmodern poppler-utils
```

From the repository root run:

```sh
python3 paper/build.py
```

The script builds in `paper/.build/local/`, runs BibTeX and enough pdfLaTeX
passes to settle references, checks the final log, and extracts the PDF text.
It rejects missing inputs, filename case mismatches, undefined references or
citations, overfull boxes, missing glyphs, unresolved editorial markers, and
unexpected placeholders. It checks the metadata abstract's 1920-character
limit and the comments field's page and figure counts.

The bundle contains only explicitly used article inputs and `main.bbl`. It
excludes the generated article PDF, logs, auxiliary files, metadata, scripts,
Git files, and repository documentation. The script extracts the archive to
`paper/.build/arxiv-extracted/`, compiles it without running BibTeX, and requires
its page count and extracted text to match the canonical build. Its archive
ordering, timestamps, permissions, and gzip header are deterministic.
The machine-readable result is `paper/.build/preflight.json`. Each run removes
the previous report, and the final upload archive is replaced only after the
extracted candidate passes its compilation and text comparison.

For a working PDF before the final metadata counts are set:

```sh
python3 paper/build.py --draft
```

This mode does not create or validate an upload package. After editing the
paper, update the page and figure counts in `arxiv-metadata.txt` and rerun the
full command. Always inspect the rendered PDF; a successful technical build
does not replace mathematical or visual review. To render pages locally:

```sh
mkdir -p paper/.build/rendered
pdftoppm -r 100 -png paper/TreeStack.pdf paper/.build/rendered/page
```

The GitHub Actions workflow `.github/workflows/paper.yml` runs the full check
on Ubuntu 24.04 with TeX Live 2023, a version supported by arXiv. Build artifacts
include the PDF, source archive, final log, extracted text, and preflight report.

## arXiv publication record and future revisions

Publication checks completed on 2026-09-25: 12 pages, no figures, a
729-character metadata abstract, no unresolved references/citations or
overfull boxes, zero publication placeholders, and identical extracted text
from the canonical and unpacked source builds. All 12 rendered pages were visually inspected. Independent
adversarial reviews checked the message, obstruction and upper-bound proofs
against the Lean development; the correspondence files record the results.
The existing Python suite passed all 23 tests, and the bounded verifier
matched all 131,958 rooted cases from 23,079 configurations on 13 trees.

The final public Palomar verification record is embedded in the article and
`arxiv-metadata.txt` as `PALOMAR-2026-09-25-000010` (https://palomar-registry.org/entry.html?id=PALOMAR-2026-09-25-000010&version=1). The full build requires that
registered record, rejects publication placeholders, and checks that the
identifier is present in the compiled PDF. Run the full build after any source
edit and inspect the resulting PDF. Personal account information, any author
identifier or affiliation, submission license, and any required endorsement
must be supplied or confirmed by the author in arXiv's submission interface.
No affiliation, ORCID, journal reference, or DOI is inferred.

Those checks were used for the successful initial arXiv submission, which is
publicly available as [arXiv:2609.31811](https://arxiv.org/abs/2609.31811).
For any future revision, regenerate `arxiv/TreeStack-arxiv.tar.gz`, choose
`main.tex` as the top-level file, use **pdfLaTeX**, and inspect the PDF
generated by arXiv before completing the replacement. The generated
`TreeStack.pdf` is for inspection and is not an input in the TeX upload bundle.
This repository workflow does not submit anything to arXiv automatically.

Official arXiv requirements were rechecked on **2026-09-25**:

- [Submission overview](https://info.arxiv.org/help/submit/index.html): preferred
  TeX source format, permitted filenames, case sensitivity, and upload review.
- [TeX submissions](https://info.arxiv.org/help/submit_tex.html): pdfLaTeX support,
  self-contained inputs, removal of extraneous outputs, and use of `main.bbl`.
- [TeX Live at arXiv](https://info.arxiv.org/help/faq/texlive.html): TeX Live 2025
  is the default; TeX Live 2023 is also supported.
- [Metadata requirements](https://info.arxiv.org/help/prep.html): portable title
  and abstract text, the 1920-character abstract limit, and page/figure counts.

The source uses ordinary BibTeX, standard packages, and no shell escape,
external document references, special fonts, or generated figure conversion.
The script checks technical portability; the submission service's compilation
and preview remain the final arXiv-side checks.

## Version 2 (prepared 2026-10-09)

Changes from arXiv v1, for the replacement upload and journal submission:

- The abstract and introduction lead with the resolution of the
  Csernák–Soukup conjecture and present the exact rooted-score criterion
  (Theorem 3.3) as a result in its own right.
- New Corollary 3.5 computes all branch messages and rooted scores with
  O(n) arithmetic operations. It is an algorithmic consequence of
  `stackableAt_iff_score_pos` and is not part of the formal development.
- The introduction cites Csernák–Soukup, arXiv:2610.09650, which proves the
  lower bound and derives the upper bound from the Almost Stacked Hypothesis.
- The provenance note is now a "Use of AI tools" statement.
- `arxiv-metadata.txt` carries the new abstract and comments.

Full preflight on 2026-10-09 (TeX Live 2023): 13 pages, 0 figures, a
1054-character metadata abstract, no unresolved references, citations or
overfull boxes, and identical extracted text from the canonical and unpacked
source builds. The Lean development and the Palomar record are unchanged.
